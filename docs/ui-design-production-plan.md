## 1 依据与已确定方向

- 业务依据：`ios-app-spec.md`，版本下限为 iOS / iPadOS 17.0，第一至第五层，以 MAA 为主要功能来源，离线截图导入、人工确认、hlsh-helper 候选集合与多路线规划；不计算节点概率。
- 美术方向：鲜明美术与原生交互结合；仅暗色；完整覆盖 iPhone 和 iPad。
- 黑流树海参考的青绿光域、紫蓝插图、有机轮廓、版画笔触和手稿图谱转化为主题视觉。功能文字、地图和输入区域保持清晰。
- 不改动既有算法、范围和开发任务；静态效果图不代表已实现或已通过设备验收。

## 2 制作步骤与验证

1. 整理规则 → 验证：视觉参数、平台版本、组件状态和业务结果语义与现有规格一致。
2. 固定合成示例 → 验证：路线、必经节点、AP 台账、加工品实例及显示数字一致。
3. 逐张生成 11 张预览 → 验证：画面布局、中文主标签、数值、状态与既定提示词一致。
4. 检查并归档 → 验证：图片可读取，记录实际尺寸、提示词和可视检查结果。
5. 更新文档入口 → 验证：README、设计规范、图片索引之间的相对链接有效。

## 3 交付文件

- `ui-design-spec.md`：视觉基础、组件、导航、业务规则、设备适配及验收要求。

## 5 完成标准与边界

11 张图片、规则文档、最终提示词及检查记录均归档后，才能记为本阶段交付完成。生成失败或实质业务语义错误须保留证据并按用户的遇错暂停要求处理。

运行交互、Dynamic Type、VoiceOver、真实截图识别、性能与原生材质效果留待实际 App 阶段验证。不得将概念图里的数字写成游戏实测结果。不得开始既有开发计划中的工程任务。
